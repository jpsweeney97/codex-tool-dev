# deliberate — close order, recovery capsule, branch table, re-runs

Reload point: the orchestrator re-reads this file at capsule construction, at every terminal, and at re-run preflight. Byte-exact content comes from the run-state store; this file carries the rules.

## Close order

1. **Exclusion check** — exactly one of: `Exclusion check: no live recorded challenge found`; `Exclusion check: live recorded challenges — X, Y`, naming the kill most worth contesting; `Exclusion check: not applicable — no exclusions recorded` (branches where Prune never cut); or `exclusion check unavailable` (eligible Contest failed — no stability claim). **Eligibility:** Contest runs on every branch whose terminal or close carries at least one validated exclusion record with `Status: active` (a record historized as `revived` never confers eligibility, and a blocked-cut disclosure is not an exclusion record), except the failure terminals (`stage failed`, `store failed`, `containment violation`, `constituent drift`, `method drift`, `evidence drift`, `capability lost mid-run`), which stop the run immediately, and the pre-stage re-run refusals (`authority conflict`, `evidence unavailable`): no stage ran this run and the records they carry are the prior run's, so an exclusion check there would claim work this run never did. Capsule validation rejects `exclusion check unavailable` unless this active-record eligibility exists under a non-failure terminal. Detection language only; works under every close shape and every eligible terminal.
2. **The recommendation or honest exit** — any of the four `making-recommendations` close shapes (`clear call`, `conditional call`, `check first`, `your call`) is a successful completion.
3. **The recovery capsule** — one paste-able fenced YAML document under `deliberate-capsule/v1`, assembled only from typed run-state items and accepted by the bundled helper against that store before display (chat-first; written to a file only on request).

**Completeness terminators:** every rendered carrier — capsule, failure capsule, emergency or bound-exceeded receipt — ends with a completeness terminator as its final key. For capsules it is `capsule-complete`, carrying a content identifier over every byte of the document strictly before the terminator line; for receipts, `receipt-complete`, computed the same way. Truncation is visible at sight, and a terminator-less or identifier-mismatched paste fails validation as incomplete rather than resuming from a partial document. The store is retired only after the carrier has finished rendering, never before.

## Capsule inventory

The capsule stores the **complete effective contract**: frame; field mode; priced constraints; stated values; soft preferences; evidence inputs and authorization; the **evidence identity** — a content identifier plus measured `bytes` for every named path at run time, source and retrieval time for web research, and for every in-packet input (pasted facts, attachments, the conversation-context capsule) a content identifier over the exact bytes the run-state store holds for it; exact path and payload identities receive their measurements from the identity helper, while an input without a stable comparable serialization may record `no comparable identity` only when ingress still exposes its byte count, otherwise the invocation is unsafely unsized and refused — with attachments and conversation capsules marked `not re-resolvable` (identifiers, measurements, and provenance only; the capsule never embeds source contents); the complete named and in-packet identity lists are re-summed against their canonical aggregate bounds whenever pins or a capsule are validated; the **method identity** — a content identifier for every deliberate-owned behavior surface: `SKILL.md`, each behavior-shaping reference (this file, `stage-packets.md`, `methods.md`, `schemas.md`, `contract-data.yaml`), and the bundled validator script with its imported production module (`scripts/_deliberate_shared.py`), recorded at setup beside the constituent pins, and enforced as the exact canonical `method-surfaces` inventory from `contract-data.yaml` wherever pins, capsules, or proof boundaries validate — a missing, duplicate, or unexpected surface fails, so drift on an unlisted surface cannot hide; survivor budget; inline-degradation permission; the **invocation wording, stored non-recursively** (capsule-only — no stage packet carries it): the initial run's raw wording, each re-run's directive text — the newest entries verbatim in `directives` within the declared directive-history bound, older entries (flag-derived entries included) collapsed to content identifiers in `directives-collapsed`, oldest first, the collapse named in the echo — and the pasted source capsule's content identifier — never a pasted capsule body, and never a supplied evidence payload (attachment and conversation-capsule bodies are identity-only under the evidence identity; inline facts the user typed into the invocation are contract wording and stay); the setup decomposition (candidate-free frame, per-candidate authority notes with provenance, per-candidate provenance flags, the normalized `soft-preferences` source, the composition-provenance spans, stakes); the full Recommend authority packet (survivor wordings, ordering with provenance, per-survivor authority notes, any overflow disclosure, stakes/reversibility); and **Recommend's registered leans**, verbatim when produced, so the capsule is closed over every envelope-recorded artifact. Capsule validation re-derives the candidate authority notes and effective-contract `soft-prefs` from that normalized source, so a pasted capsule cannot move candidate-attached language into a candidate-neutral packet. Each field named by `validation.echo-contract-fields` stores `{value, provenance}` so an import restores the exact echo; evidence identity, method identity, bounds, and invocation wording carry their declared direct shapes, except an echo-only `store failed: write` capsule marks both pin-derived identity members `not produced: pins not written`.

Then the field, stored separately from its candidate provenance, plus the required top-level `field-order-origin`: `user-supplied` or `generate-produced` whenever a field exists, and `not produced: <reason>` iff the original field is absent. The origin is independent of current field mode: latest validated Generate fixes `generate-produced`; otherwise import preserves the prior origin; an initial or newly supplied closed field fixes `user-supplied`; adopting a prior full generated field as closed preserves `generate-produced`, so current mode never launders generated order into user lean.

```text
Original field:       <complete generated or user-supplied field — present whenever any field was validated; `not produced: <reason>` only on a failure before Generate returned a validated field>
Generation boundary:  <untouched-fixed-points line | Generate not run: closed-to-widening | not produced>
```

Then prior survivors, any disclosed budget overflow with its blocked-cut disclosures, every exclusion and disposition record with its `Status`, the run's accepted `retrievals` in full — each with producing stage, source, retrieval time, and effective `concerns` — and — verbatim when produced, `not produced` otherwise — Shape's comparison surface and recorded constraint consequences, Recommend's close and terminal claim, and the rendered exclusion check line. The Recommend authority packet's order-provenance is mechanically derived from `field-order-origin` through the canonical label map and cross-checked, never an independent claim. A revived option rejoining a reused field carries `insertion: original-field-position`; a canonically accepted seed appended to that field carries `insertion: appended-by-rule`; prior-full-field adoption and a fresh Generate output have no insertion event. Prune preserves every carried insertion value byte-exact. Then the provisional rerun seed: exact `not applicable` when Recommend completed without one, `not produced: <reason>` only when Recommend is absent or invalidated, or an unaccepted `{wording, handle, core-idea, distinct-bet}` mapping with every value non-empty. No import normalizes one empty carrier into the other: a restart after Contest preserves `not applicable`, while invalidating Recommend replaces it with `not produced: <reason>`. Then revival instructions and, as the final content field, **the single proof boundary**:

- packet isolation achieved or not — claimed only when every stage that ran was fresh on a helper-rendered brief whose render identifier is recorded in run state, with intentionally skipped stages listed and the behavioral residuals named: verbatim dispatch of the rendered bytes, and evidence-content exposure under the read-isolation line
- the read-isolation line (`packet-field isolation only; evidence-content encounters: none reported | <listed>`)
- the pinned constituent source set (the full resolved set: paths and content identifiers) and the method identity
- effective models at their provenance — introspected ground truth, `self-reported: <value>`, or `unknown`, with disagreeing ambient sources recorded as the disagreement; evidence scope actually used
- containment class (behavioral vs runtime-enforced; snapshot detection is net-Git-visible only)
- the run-state store path, any history-compaction collapses, and what none of it proves — always including that cross-section coherence of the assembled artifact is unvalidated: sections are stage-local judgments, byte-faithful, never reconciled

Nothing outside the capsule re-renders the proof boundary; a close that displays it displays the capsule's field verbatim. `not generated` never means `field unavailable`.

**Closure claim, exactly:** the capsule is closed over restart for **control state**. A resume rebuilds any stage's matrix packet, including a Recommend-only or Contest-only restart, from the capsule plus re-resolved evidence — named paths re-read live against the stored identifiers, attachments and conversation capsules re-supplied by the user, and a required input that resolves neither way exits `evidence unavailable`. The rebuild is executable, not aspirational — proven at fixture grain: the helper's `import-capsule` command validates the pasted capsule as a fully typed terminal/artifact state and atomically publishes the re-run store — echo (per-field provenance restored), decomposition, mandatory freshly re-resolved pins, `capsule-import`, and a reserved `restart-plan` containing the earliest invalid stage, classified reasons, and the typed directive bindings — from which `render-brief` composes the restart packet. Imported stage artifacts strictly before the frontier remain byte-exact; stage artifacts at or after it are unavailable until superseded by new accepted envelopes, and no prior envelope is ever synthesized. The capsule alone never claims to stand in for evidence it deliberately does not embed.

**Construction and acceptance are store-backed.** Before a healthy-write capsule or failure capsule is accepted, `record-proof-inputs` writes the reserved proof-boundary body byte-exact except for its store locator: the helper realpath-compares that locator with the live store and persists its own canonical root. In a separate fail-fast call, `record-terminal` writes the reserved `{terminal, carrier}` state (`carrier: capsule | failure-capsule`). Every store-mutating helper is the sole mutation in a dedicated `set -euo pipefail` call under `references/stage-packets.md`; the first nonzero helper result ends every later helper invocation for that run, including corrected or diagnostic validation probes, and only contract-selected receipt rendering or cleanup may follow without invoking the helper. The orchestrator serializes capsule fields only from typed store items, then `validate-capsule --store <store> --accept <capsule>` compares every store-derived value — contract, decomposition, field and field-order origin, survivors and insertion provenance, records and retrievals, surface and consequences, close and registered leans, mandatory terminal claim, exclusion check, terminal state, and the complete proof boundary — before the capsule can render; acceptance alone writes the reserved `capsule-progress` item. If Contest failed, the underlying terminal and any stored terminal claim stay unchanged while the exclusion-check field alone becomes `exclusion check unavailable`. A paraphrased close, trimmed record, reordered field, memory-composed value, missing claim, invalid terminal/artifact combination, terminal outside the canonical classes, artifact past its terminal's class frontier, duplicate YAML key, malformed nested value, a bounds map that is empty, partial, or different from canonical, or over-bound history fails. Store failure never weakens source fidelity: `store failed: read` gets an emergency receipt, while `store failed: write` is the narrow circularity exception that validates its failure capsule with `--store` but cannot require new proof-inputs, terminal-state, or `--accept` writes on the failed path. Every capsule validation path — construction, paste, import — also enforces the wording canonical-form gate: option wordings (original field, survivors, record options, decomposition candidates, provisional seed) must be in canonical whitespace form; a capsule carrying a non-canonical wording predates wording canonicalization and is rejected as legacy — re-run the deliberation — never silently reinterpreted, because the completeness terminator hashes raw bytes. When setup failed after the echo but before decomposition, the capsule's decomposition is deterministically re-derived from the echo's normalized setup source; when pins were never written, effective-contract evidence and method identity plus proof-boundary constituent and method pins are all `not produced: pins not written`, and store comparison rejects any pin-derived value in their place. Import is necessarily storeless but runs the same full typed and cross-field validation before any new store is created.

## History compaction

The directive-history rule is standing and helper-owned, with an executable transition: at every import the newest eight directive entries stay verbatim in `directives` while older entries — flag-derived entries such as `revive: <wording>` included — collapse to content identifiers appended to `directives-collapsed`, oldest first, so re-run continuity never dies at the history bound; continuity is checked logically (the prior collapsed list preserved exactly, the prior verbatim list an exact prefix of the new one before compaction). When the chat-capsule bound binds, compaction runs in a fixed order — older directive texts beyond the verbatim eight (that same standing rule), then `revived`-historized records, then prior-run retrieval fact bodies (source, retrieval time, and `concerns` always retained) — each item collapsing to its content identifier with the collapse named in the proof boundary. A capsule that still cannot fit produces the recovery-carrier terminal `capsule bound exceeded`: the underlying semantic terminal and any terminal claim remain stored unchanged, the close and exclusion check stand, the bound-exceeded receipt names what remains oversized, and the store is retained until the user explicitly directs a file-written complete capsule or declines. On that request, `validate-capsule --file-capsule` applies the larger `capsule-file-bytes` cap and the file capsule retains the underlying terminal; import likewise requires `import-capsule --file-capsule`. This is the one recovery terminal where retirement waits on direction, because teardown never precedes the recovery carrier's availability. Collapsed history never becomes authority again: it is identity-only, enters no packet, and a resume that would need it treats it as `not re-resolvable` evidence.

## Receipts

**Failure capsule** — the standard typed capsule shape with only artifacts durable before the triggering failure preserved; values returned or written after that point are never recovery authority, and the failed artifact plus every downstream artifact is `not produced: <reason>`. The terminal is recorded in the reserved terminal state when the write path remains healthy; this is the carrier on failure terminals because the pasted capsule is the only defined resume input. Valid resume input; resume restarts at the failed stage or the earliest earlier stage whose artifact is absent or invalid. A pre-field failure capsule (`Original field: not produced`, `field-order-origin: not produced`) is valid resume input whose resume restarts at Generate. An echo-only setup failure carries the helper-derived normalized decomposition but no pin-derived identity or proof state.

**Emergency receipt** — rendered instead of any capsule whenever the failed component is the validation helper (cannot run, cannot be bootstrap-verified because the platform hasher is unavailable, or is itself the drifted surface) or the run-state store's read path: echo, terminal name, failed component, last validated stage by name, and the statement that no resumable capsule exists. Explicitly non-resumable, never validated, never claiming capsule shape; pasting a receipt is preflight `invalid invocation`, and the next run starts from scratch. Recovery never depends on the component that just failed.

**Dirty-state receipt** (`containment violation`): the changed paths, the pre- and post-stage snapshot identities, the stage charged, and the statement that side effects outside the worktree remain unverified. The orchestrator never silently restores the worktree and never adopts the mutation; the run stops for user direction.

**Bound-exceeded receipt** (`capsule bound exceeded`): names what remains oversized after full compaction; non-resumable in chat. On explicit request, the complete capsule is validated and written under `capsule-file-bytes`, keeps its underlying semantic terminal, and is valid resume input only through `--file-capsule`.

## Branch table

Totalized, with every branch emitting only artifacts that exist (`not produced` / `not applicable` otherwise):

| Unsupported invocation context (cron, hook, scheduled task, another skill), where detectable | `unsupported invocation context` — pre-spend | echo only |
| Muddy goal at Generate | exit naming `outcome-shaping` | echo only |
| One right answer at Generate | that honest terminal | echo only; any partial idea stays in the exit prose and is not accepted as a field artifact |
| Zero survivors | `no candidate survives the confirmed cuts` | echo, field, exclusion records, exclusion check, capsule |
| One survivor | `one candidate survives the authorized cuts; no comparative recommendation was performed` — survivor, rivals' exclusion basis, smallest next lane | echo, field, records, exclusion check, capsule |

| Field collision unresolved in Shape | that terminal | echo, field, records, partial surface, exclusion check, capsule |
| Authority gap in Shape | that exit | same as above |
| Field-not-ready from Recommend | that exit, seed recorded | all but close |

| Capability unavailable at preflight, no degradation permission | that exit, pre-spend | echo only |

| Stage failure / malformed packet | `stage failed: <stage>` | echo, failure capsule (validated artifacts only) |

| Evidence drift mid-run | `evidence drift` | echo, failure capsule (validated artifacts only) |
| Contest fails on an eligible branch | the underlying terminal stands; `exclusion check unavailable` — no stability claim | all underlying artifacts; the capsule keeps the underlying terminal and terminal claim, stores `exclusion-check: exclusion check unavailable`, and resume may restart at Contest alone |

Any constituent honest exit without its own row terminates under the global exit rule and emits the echo, every artifact validated before the exiting stage, and — whenever a field exists — the capsule, with the exclusion check whenever exclusion records exist. Its terminal is recorded canonically as `constituent exit at <stage>: <the named exit>`: Shape and Recommend are the capsule-bearing exit stages, an exit at Generate leaves no field and stays echo-only, and validation enforces the named stage as the artifact frontier — a terminal matching no canonical class and not this form is refused, never accepted as free-form authority. Every close-less capsule-bearing row with active records also carries the stored terminal claim, even where the artifact column abbreviates it.

A user-revived option joins on user authority, may exceed the budget, and evicts nothing.

A validated stage envelope whose status is `failed: pin mismatch — constituent:<path>` takes the constituent-drift row; `failed: pin mismatch — evidence:<path>` takes the evidence-drift row; `failed: pin mismatch — method:<path>` takes the method-drift row. These classified failures never fall through to `stage failed: <stage>`; every other failed envelope does.

## Re-runs

One principle: **restart at the earliest stage whose input or required artifact became invalid.** The transitions are derived from the stage packet matrix — a changed input invalidates the earliest stage whose column carries it — and any narrower transition states its testable reason inline. Where Generate never ran (`closed-to-widening`), a restart at Generate resolves to Prune.

**Normalization, fixed application order** (before any restart derivation): first, contract-field changes (frame, field mode, constraints, values, evidence and authorization, budget, soft preferences, stakes, degradation permission) produce the effective re-run contract; second, revival directives apply against the active record set under that effective contract — the `authority conflict` lookup runs here, so a payload that revives a constraint-cut option and withdraws or reprices that constraint in the same breath passes; third, the no-argument provisional-seed acceptance flag applies, accepting exactly the stored seed's canonical `wording`; fourth, re-resolved source and evidence drift contributes explicit, already classified `--invalidate-from <stage>` frontiers; fifth, the implicit resume directive — an unfinished-run capsule (its recorded terminal in the failure set: `stage failed`, `store failed: write`, `containment violation`, `constituent drift`, `method drift`, `evidence drift`, `capability lost mid-run`; or its stored exclusion check line `exclusion check unavailable`) requests its missing artifacts by construction, no typed directive required. A directive that resolves to none of these classes is preflight `invalid invocation` naming the unclassifiable directive, never guessed into a class — and the binding is mechanical, not honor-system: new raw directive texts supplied to `import-capsule` require a typed directive manifest (`--directive-manifest`) pairing each text with its applied actions, orphan text (a directive bound to no applied action) and orphan actions (an applied action bound to no directive) refuse before the store is staged, and the accepted bindings are stored in `restart-plan.directives`. The helper writes the earliest applied frontier and every reason into `restart-plan`; a completed capsule with no classified change or invalidation is refused before store creation. A closed-to-seed mode transition first harvests every prior field candidate into decomposition, then marks the imported field, generation boundary, and order origin `not produced` because Generate now owns their replacements. Whenever the restart is Generate, every user-authorized candidate enters Generate as a collapse-exempt seed — import changes an existing revived candidate's provenance to `revived`, and accepted candidates to `accepted`, before seed rendering; the seeds item renders every non-`generated` provenance flag (`user-seed`, `revived`, `accepted`, `adopted`), so a user-authorized candidate never silently drops from regeneration. Rejoin-at-original-position applies only when the stored field itself is reused — historized records stay historized, and revival's pin against delegated cuts survives regeneration. Declared bounds are immutable v1 constants from `references/contract-data.yaml`; the capsule and echo retain the exact canonical map, and any invocation, pasted capsule, echo override, or re-run directive that differs is preflight `invalid invocation` before store creation.

**Evidence authority is live, checked by identity:** at re-run the orchestrator re-resolves every named evidence path and compares content identifiers against the capsule's evidence identity, and re-supplied in-packet material (attachments, conversation capsules, pasted facts) is hashed over its bytes as received and compared the same way — a mismatch, or any input whose stored identity is `no comparable identity`, is changed evidence restarting at its first consuming stage, never inheriting the artifacts the original produced. Drift at an unchanged path invalidates every stored artifact built downstream; the matrix routes the evidence item to every stage, so drift in run-supplied evidence restarts at the first stage that ran, and an input first added by a prior re-run directive restarts where it first entered. (Mid-run, the same mismatch is the terminal `evidence drift`; at re-run, drift is expected and routes here.) A required evidence input that no longer resolves — a missing path, an expired attachment marked `not re-resolvable` — exits as `evidence unavailable` rather than silently reusing the stored field. Web-research facts are not re-fetched wholesale: the capsule's retrieval-time provenance makes their age visible; staleness in the survivor share routes through Recommend's unstable-fact rule under the echoed authorization — the only share Recommend's packet carries — and excluded-fact freshness is user-owned by disclosure: no stage revalidates a fact that supports only an active exclusion record, so every re-run echo surfaces each active record-cited retrieval with its source and retrieval time, and a revival directive stays the lane for acting on a fact the user knows has moved.

**Transitions:**

- Only a revival directive changed, and no accepted provisional seed is active → skip Generate and Prune; revival is a full active-state transition, then a cardinality branch — never an unconditional Shape dispatch. The transition: the revived option's exclusion record is marked `revived` — retained in the capsule as history, no longer an active exclusion, out of Contest's eligibility basis and excluded share; its candidate provenance becomes `revived` even when it was formerly `generated`, so any later combined Generate restart carries it as a seed; its authority note moves to the survivor share; the option rejoins at its original field position on user authority with `insertion: original-field-position`. Then the standing cardinality branches apply to the resulting survivor set: two or more → Shape runs on it; exactly one → the one-survivor terminal, Shape and Recommend never launch; Contest, when eligible, receives only the still-active records.
- Frame change → Generate. Field-mode change re-decides the field's origin: landing on `closed-to-widening` starts at Prune over one explicit base — `prior seeds only` (generated options drop, the drop named in the echo; the newly user-chosen base gets `field-order-origin: user-supplied` and `Generate not run: closed-to-widening`), `prior full field` (generated options are thereby adopted as fixed candidates, the adoption named in provenance, while both the imported fixed-points boundary and `field-order-origin: generate-produced` remain honest), or a newly supplied candidate list (`user-supplied` with the not-run boundary); a mode-change directive without a base is preflight `invalid invocation`, never a silent default. Landing on `seed-and-widen` starts at Generate with the prior candidate set as collapse-exempt seeds and the new field origin `generate-produced` — widening only adds, so no base question arises.
- Constraint change → regenerate under `seed-and-widen`: the matrix routes constraints to Generate as generation-controlling context, and `ideate` relaxes, moves, and inverts them as provocations, so a changed constraint can produce a mechanism-distinct option the stored field never contained. Under `closed-to-widening`, the Generate-never-ran rule resolves the restart to Prune. No `could this alter the field?` judgment is left to the orchestrator.
- Values change → regenerate: the matrix routes stated values to Generate as generation-controlling context, and no narrower reason survives that.
- Evidence content or authorization change → restart per the drift rule above; an expanded authorization is a Generate-consumed input (new sources can expose mechanism-distinct options), so it regenerates.
- Budget change → re-prune: Prune is the budget's earliest consumer.
- Soft-preference or stakes change → re-shape the stored survivors: Shape is their earliest consumer.
- Degradation-permission-only change (execution-only) → preserve every artifact and re-echo execution mode.
- A revived option is pinned against delegated budget, equivalence, and dominance cuts after any re-prune. Constraint compatibility is never an orchestrator judgment: preflight makes only a mechanical record lookup — a revival directive whose target's active exclusion record carries cut basis `constraint` must also withdraw or reprice that constraint (a contract change, restarting per the constraint-change transition); a directive that does not is refused as `authority conflict` before any stage launches. Any other conflict between a revived option and an active constraint is found where constraint judgment lives, isolated and ledgered: Shape records the consequence, Recommend owns the filter and its disposition record, and Contest receives the challenge — never a preflight refusal.
- **Accepted provisional seeds split by field mode.** `--accept-seed` is a no-argument authorization to accept exactly the capsule's stored provisional seed; the seed's required canonical `wording` becomes the candidate wording, so arbitrary CLI text can never mint a candidate. Under `seed-and-widen`, that accepted candidate is a new Generate input: Generate reruns and widens around it, collapse-exempt like any seed — the direct-to-Prune shortcut would freeze the field around an option Generate never saw. Under `closed-to-widening`, acceptance is the user adding the candidate to their reused closed field: import appends it to both decomposition and the effective Prune field with provenance `accepted` and `insertion: appended-by-rule`, and re-prunes directly with no widening. The minimum seed shape is `{wording, handle, core-idea, distinct-bet}` by construction.
- A provisional seed stays provisional until the user explicitly accepts it. Changing field mode does not itself accept the seed; if a newly named candidate base contains that wording, it enters under that base's adoption rule. Relaunching with any unrelated directive is not acceptance, and a seed never auto-widens a `closed-to-widening` field.

**Source-drift invalidation map:** a re-run re-resolves and re-pins the live constituents and `deliberate`'s own surfaces against the capsule's recorded identities; those identifiers are evidence of what governed the prior run, never a freeze against evolution. Drift is disclosed in the echo and proof boundary **and converted into invalidation**, by a canonical map total over the pinned method-identity surfaces at the same file grain the pins record: `ideate` sources → Generate; `option-shaping` sources → Shape; `making-recommendations` sources → Recommend; `references/methods.md` → Prune (the pinned identity is a whole-file hash that cannot attribute a change to one method, so the earliest method consumer restarts — Contest-only drift is indistinguishable at that grain and deliberately over-invalidates); every other deliberate-owned method surface — `SKILL.md`, `references/capsule.md`, `references/stage-packets.md`, the canonical data file, `references/schemas.md`, the validator, and any future pinned surface not given a narrower mapping — defaults to Generate, so no prior field or downstream artifact crosses current-validator revalidation. A capsule under a schema version the current validator does not support and no shipped migration converts is refused at preflight, never reinterpreted. The resume restarts at the earliest of the directive-derived stage and every drifted surface's mapped stage, regenerating the invalidated artifacts under the current method with the drift named — disclosure accompanies invalidation, never substitutes for it, and no artifact produced under a changed method is reused, silently or confessedly. The pasted capsule is orchestrator input: its prior judgments (records, close, proof boundary) enter a stage packet only where that stage's checklist names them.
